## 2. New findings from this pass (not in the July audit)

### F1 — No `.dockerignore` on either build context ✅ fixed in this PR

`api/Dockerfile` and `frontend/Dockerfile` both do `COPY . .` with no
`.dockerignore`. Consequences: the api production image shipped `tests/`
(1.3 MB) and tool caches, a local `api/.env` **would have been baked into the
image** (secret-leak risk), and a local `frontend/node_modules` was sent to the
daemon and could overwrite the freshly `npm ci`'d deps in the builder stage.
Fixed: `.dockerignore` added for both contexts. CI runs pytest on the host and
dev compose bind-mounts source, so no workflow changes.

### F2 — `eslint-config-next` stuck one major behind `next` ✅ fixed in this PR

`next ^16.2.10` with `eslint-config-next ^15.5.20`. Root cause: dependabot
ignores **all** major bumps (deliberate policy), so when `next` was bumped
15→16 manually, its ESLint config wasn't. The dependabot `nextjs` group keeps
them in sync only for minor/patch. Fixed: bumped to `^16.2.10`; lint (0 errors)
and `tsc --noEmit` verified.

*Follow-up habit:* any manual major bump must sweep its dependabot group
partners in the same PR.

### F3 — Test dependencies ship in the production image → BITB-073

`api/requirements.txt` includes `pytest` / `pytest-asyncio`, so every prod
image carries the test framework. Split into `requirements.txt` (runtime) +
`requirements-dev.txt` (`-r requirements.txt` + test/lint tools). Touches:
`api/Dockerfile` (nothing — it keeps installing runtime only), 2 workflows
(`test_update.yml`, `azure-deploy.yml` cache keys + install lines), `Makefile`
(2 targets), `safety check` invocations. Small but multi-file — its own PR.

### F4 — Repo-root doc rot ✅ fixed in this PR (relates to audit D7)

`AGENTS.md.old` and `AGENTS.old.md` were dead duplicates of `AGENTS.md`.
`NEXT_STEPS.md`, `MULTILINGUAL_PROGRESS.md`, `TEST_COVERAGE.md` were frozen
2026-01 planning docs presented at top level as if current. Deleted the first
two; moved the rest to `docs/archive/` with an index README; updated the three
backlog stories that referenced them.

### F5 — Dependabot has no `gradle` ecosystem → small follow-up

Android dependencies (version catalog in `android/`) get OWASP CVE scanning
(`android-dependency-check.yml`) but **no automated update PRs** — npm, pip,
GitHub Actions, and Docker all do. Add a `gradle` entry to
`.github/dependabot.yml` mirroring the existing ignore-majors policy.
One-file change; ship any time.

### F6 — Six `docker-compose*.yml` variants (relates to audit O1)

`docker-compose.yml`, `.dev`, `.prod`, `.local-prod`, `.local-prod-acr-be`,
`.gpu` — six files with duplicated service definitions that drift
independently. Consider a base + `docker compose -f base -f override` or
profiles. **Defer** — the Makefile targets hide the complexity today and the
consolidation risks breaking muscle memory; do it opportunistically when one of
the files next needs a real change.

### F7 — Makefile at 934 lines / 97 targets

Approaching unmaintainability but well-organized. When it next hurts, split
into `mk/*.mk` includes (docker, test, android, deploy) with the root Makefile
as an index. **Defer** — no urgency, cosmetic risk only.
